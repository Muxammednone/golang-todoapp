# TodoApp API

Учебный backend на Go для управления личными задачами. Регистрация и вход вынесены в отдельный gRPC-сервис SSO. TodoApp предоставляет HTTP API, проверяет JWT и ограничивает доступ к задачам их владельцем.

## Возможности

- Регистрация и вход через SSO; пароли хранятся в SSO как bcrypt-хеши.
- Создание профиля TodoApp, связанного с аккаунтом SSO.
- Создание, просмотр, изменение и удаление своих задач.
- Пагинация списка задач, отметка выполнения, статистика за период.
- Проверка JWT HS256 и срока действия токена.
- Проверка владельца в SQL: чужие задачи возвращают `404`.
- Миграции PostgreSQL, структурированные логи, корректное завершение приложения.

## Архитектура

```text
Postman / HTTP-клиент
        |
        v
TodoApp HTTP API :5050 ---- gRPC ----> SSO :50051
        |                                |
        v                                v
PostgreSQL TodoApp :5432           PostgreSQL SSO :5433
```

Репозитории:

- [golang-todoapp](https://github.com/Muxammednone/golang-todoapp) — HTTP API, профили, задачи, статистика.
- [sso](https://github.com/Muxammednone/sso) — регистрация, проверка пароля и выдача JWT.
- [sso-proto](https://github.com/Muxammednone/sso-proto) — protobuf-контракт и сгенерированный Go-клиент. Оба приложения используют модуль версии `v0.4.0`; генерировать контракт для запуска не нужно.

Внутри TodoApp код разделён на HTTP transport, service и PostgreSQL repository. Аккаунт SSO и локальный профиль имеют разные ID: связь хранится в `users.sso_user_id`. Владельцем задачи служит ID локального профиля. Он определяется сервером, а не передаётся клиентом.

## Требования

- Go 1.26.5 или новее.
- Docker с Compose; на Windows — запущенный Docker Desktop с Linux containers.
- Task CLI (`task`).
- Свободные локальные порты `5050`, `50051`, `5432`, `5433`.

## Локальный запуск

Приложения запускаются на хосте, базы — в Docker. Команды ниже выполняются из корня соответствующего репозитория.

### 1. Запустить SSO

Следуйте [README SSO](https://github.com/Muxammednone/sso#readme): создайте его `.env`, поднимите базу, примените миграции и выполните `task run` в отдельном терминале.

### 2. Настроить TodoApp

Скопируйте `.env.example` в `.env` и заполните его. Пример для локальной разработки:

```dotenv
HTTP_ADDR=127.0.0.1:5050
HTTP_SHUTDOWN_TIMEOUT=5s
POSTGRES_USER=todoapp
POSTGRES_PASSWORD=todoapp_local_password
POSTGRES_DB=todoapp_local_dev
POSTGRES_TIMEOUT=5s
LOGGER_LEVEL=DEBUG
TIME_ZONE=UTC
SSO_ADDR=127.0.0.1:50051
SSO_TIMEOUT=5s
JWT_SECRET=<тот же случайный секрет, что в SSO>
```

Замените значение `JWT_SECRET` на секрет из SSO длиной не меньше 32 байт. Не публикуйте `.env`. Пароль базы в примере предназначен только для локального запуска.

`task run` загружает `.env`, задаёт `POSTGRES_HOST=127.0.0.1`, папку логов `out/logs` и отключает CGO. Taskfile также задаёт `PROJECT_ROOT`, необходимый Compose. При запуске напрямую через `go run` эти переменные нужно установить самостоятельно.

### 3. Поднять базу и приложение

```sh
task db:up
task db:migrate
task run
```

Если база ещё запускается и миграция получила ошибку соединения, дождитесь её готовности и повторите `task db:migrate`.

API: `http://127.0.0.1:5050/api/v1`. SSO должен продолжать работать в отдельном терминале.

| Команда | Назначение |
| --- | --- |
| `task run` | Запустить HTTP API |
| `task build` | Собрать все Go-пакеты |
| `task db:up` | Поднять PostgreSQL и проброс порта |
| `task db:migrate` | Применить миграции |
| `task db:status` | Проверить контейнеры базы |
| `task db:down` | Остановить базу и проброс порта, сохранив данные |

Не используйте общий `docker compose up` как замену этому сценарию: контейнер приложения в текущем Compose ещё не настроен для связки с SSO.

## Проверка API через Postman

Создайте переменные `base_url=http://127.0.0.1:5050/api/v1` и `token`. Для JSON-запросов выберите Body → raw → JSON.

### Регистрация и вход

`POST {{base_url}}/auth/register`:

```json
{"email":"demo@example.com","password":"Demo-password-123!"}
```

Ответ `201`: `{"user_id":123}`. Это ID аккаунта SSO.

Отправьте такое же тело в `POST {{base_url}}/auth/login`. Ответ `200` содержит `access_token`. Сохраните его в `token`.

Для всех следующих запросов установите Authorization → Bearer Token → `{{token}}`, либо заголовок:

```http
Authorization: Bearer <access_token>
```

### Профиль

`POST {{base_url}}/me`:

```json
{"full_name":"Demo User"}
```

Ответ `201` содержит профиль TodoApp. Повторное создание возвращает `409`. Для чтения используйте `GET {{base_url}}/me`.

Профиль нужен для задач и статистики. Если аккаунт существует, но профиль ещё не создан, эти маршруты возвращают `404`. `GET /auth/me` проверяет аккаунт по JWT и возвращает `sso_user_id`, а `GET /me` читает локальный профиль.

### Задачи

`POST {{base_url}}/tasks`:

```json
{"title":"Проверить API","description":"Создать и завершить первую задачу"}
```

Используйте `id` из ответа вместо `<id>`:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/tasks?limit=10&offset=0` | Свои задачи |
| GET | `/tasks/<id>` | Одна своя задача |
| PATCH | `/tasks/<id>` | Изменить задачу |
| DELETE | `/tasks/<id>` | Удалить задачу; ответ `204` |
| GET | `/statistics` | Статистика своих задач |
| GET | `/statistics?from=2026-10-01&to=2026-11-01` | Статистика задач по дате создания: начало включительно, конец не включительно |

Пример тела PATCH:

```json
{"completed":true}
```

Можно менять `title`, `description`, `completed`. Отсутствующее поле сохраняется; `description: null` очищает описание. `title` и `completed` не могут быть `null`.

`author_user_id` в теле и `user_id` в query не выбирают владельца: сервер использует профиль из контекста авторизации. Для проверки изоляции зарегистрируйте второй аккаунт, создайте ему профиль и убедитесь, что он не видит задачи первого, а GET/PATCH/DELETE чужой задачи возвращают `404`.

### Ошибки

| Код | Значение |
| --- | --- |
| 400 | Неверный запрос |
| 401 | Неверные данные входа, отсутствующий, неверный или истёкший токен |
| 404 | Нет профиля, задача отсутствует или принадлежит другому аккаунту |
| 409 | Аккаунт/профиль уже существует либо конфликт обновления задачи |
| 503 | SSO недоступен |
| 504 | Истёк срок ожидания вызова SSO |
| 500 | Внутренняя ошибка; детали остаются в логах |

## Swagger UI

После запуска TodoApp откройте `http://127.0.0.1:5050/swagger/index.html`.

1. Выполните `POST /auth/register`, затем `POST /auth/login` через **Try it out**.
2. Скопируйте `access_token` из ответа.
3. Нажмите **Authorize** и введите `Bearer <access_token>` целиком, с префиксом `Bearer`.
4. Создайте профиль через `POST /me`, затем используйте маршруты задач и статистики.

Схема использует адрес сервера, с которого открыт Swagger, без жёстко заданного IP. Регистрация и вход публичные; остальные операции требуют JWT.

Для обновления схемы после изменения Go-аннотаций:

```sh
task swagger
```

Команда использует swag v1.16.6 и обновляет `docs/docs.go`, `docs/swagger.json`, `docs/swagger.yaml`. При первом запуске нужен доступ к загрузке Go-модулей.

## Проверки

```sh
task build
go test ./...
```

Интеграционный тест `TestTaskOwnershipIntegration` по умолчанию пропускается. Для запуска на локальной мигрированной базе передайте `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `POSTGRES_TIMEOUT`, `POSTGRES_HOST=127.0.0.1` и `TODOAPP_INTEGRATION=1` в окружение, затем выполните:

```sh
go test ./internal/features/tasks/transport/http -run TestTaskOwnershipIntegration -count=1 -v
```

Обычный `go test` сам `.env` не загружает. Тест создаёт два временных профиля, проверяет HTTP-маршруты с JWT и настоящей PostgreSQL, затем удаляет свои данные. Работающий SSO для этого теста не требуется.

## Границы проекта

Текущая версия предназначена для работы через API. Старый веб-интерфейс ещё не адаптирован к авторизации. Для работы используйте Swagger UI или HTTP-клиент. Публичные маршруты `/users` отключены. Старые профили без `sso_user_id` автоматически к аккаунтам не привязываются.

Refresh-токены и отзыв JWT не реализованы: после истечения токена нужен повторный вход. Приведённый локальный запуск использует HTTP и gRPC без TLS. Конфигурация публичного развёртывания в этот сценарий не входит.
